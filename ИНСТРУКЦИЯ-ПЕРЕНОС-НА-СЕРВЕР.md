# Перенос сайта Dominoki на свой сервер

Полная инструкция: с Netlify → ваш VPS + поддомен + HTTPS.
Команды копируются по очереди. Нужны: IP сервера, пароль от сервера, ваш домен.

> Команды рассчитаны на вход **root**. Если вы вошли под другим пользователем —
> ставьте `sudo` перед каждой командой.

---

## Шаг 1. Создать поддомен (запись DNS)

1. Откройте панель того, где куплен домен (reg.ru, ru-center, timeweb и т.п.).
2. Найдите раздел **DNS-записи** / **Управление доменом** / **DNS-зоны**.
3. Добавьте новую запись:

| Поле | Значение |
|---|---|
| Тип | **A** |
| Имя (хост) | `refs` (или любое другое, например `site`) |
| Значение / IP | **IP-адрес вашего сервера** |
| TTL | авто (или 3600) |

4. Сохраните. Обновление занимает от 5 минут до суток (обычно сразу).

Ваш будущий адрес: **`refs.ваш-домен.ру`** (дальше в инструкции заменяйте
`refs.ВАШ-ДОМЕН.РУ` на него везде, строчными буквами).

---

## Шаг 2. Сделать репозиторий открытым

Код сайта лежит на GitHub, и сервер должен его скачать.

1. Откройте <https://github.com/antigravity1980/dominoki-ref>
2. **Settings** → внизу, раздел **Danger Zone** → **Change visibility** → **Make public** → подтвердите, введя имя репозитория.

Зачем: чтобы сервер скачал код без паролей. Секретов в коде нет — ключи
(Groq, пинкоды) хранятся только на сервере в файле `.env`, на GitHub их никто не увидит.

---

## Шаг 3. Подключиться к серверу

На компьютере откройте **PowerShell** (Пуск → «PowerShell») и введите:

```
ssh root@IP-ВАШЕГО-СЕРВЕРА
```

- Первый раз спросит `Are you sure you want to continue?` — ответьте `yes` и Enter.
- Пароль — из письма хостера. При наборе символы не отображаются — это нормально, просто введите пароль и Enter.

---

## Шаг 4. Установка (копируйте команды по одной)

```bash
apt update
apt install -y git curl
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v
```

`node -v` должно показать `v22.x.x`. Дальше:

```bash
git clone https://github.com/antigravity1980/dominoki-ref.git /opt/dominoki
cd /opt/dominoki
cp .env.example .env
nano .env
```

Откроется редактор. Стрелками поставьте курсор на строку
`GROQ_API_KEY=...`, удалите подсказку и вставьте **свой ключ Groq** —
тот же, что был на Netlify (<https://console.groq.com> → API Keys, ключ вида `gsk_...`).
Вставка в терминале — правой кнопкой мыши или `Shift+Insert`.

Там же придумайте свой 4-значный `ADMIN_PIN` (например `4829`).

Сохранение: `Ctrl+O` → Enter. Выход: `Ctrl+X`.

---

## Шаг 5. Быстрая проверка

```bash
node server.mjs
```

Увидите `Dominoki запущен: http://127.0.0.1:3000`. В отдельном SSH-окне
(или после `Ctrl+C`) проверьте:

```bash
curl -s localhost:3000 | head -3
```

Должен начаться с `<!DOCTYPE html>`. Если так — всё работает. Остановите
тестовый запуск кнопками `Ctrl+C`.

---

## Шаг 6. Автозапуск (сайт работает всегда, даже после перезагрузки)

```bash
cat > /etc/systemd/system/dominoki.service <<'EOF'
[Unit]
Description=Dominoki
After=network.target

[Service]
WorkingDirectory=/opt/dominoki
ExecStart=/usr/bin/node server.mjs
Restart=always
EnvironmentFile=/opt/dominoki/.env

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now dominoki
systemctl status dominoki --no-pager
```

Статус `active (running)` — успешно.

---

## Шаг 7. Перенести существующие данные с Netlify

> Важно: сделайте это **до** отключения Netlify, пока сайт там ещё работает.

```bash
cd /opt/dominoki
node migrate.mjs https://dominoki.netlify.app
```

Скрипт скачает все референсы, комментарии и вложения в папку `data/` —
это ваше постоянное хранилище на сервере. В конце напишет `Готово!`.

---

## Шаг 8. Nginx (прокси на сайт)

```bash
apt install -y nginx
cat > /etc/nginx/sites-available/dominoki <<'EOF'
server {
    listen 80;
    server_name refs.ВАШ-ДОМЕН.РУ;
    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
ln -sf /etc/nginx/sites-available/dominoki /etc/nginx/sites-enabled/dominoki
nginx -t && systemctl reload nginx
```

**Не забудьте** в блоке выше заменить `refs.ВАШ-ДОМЕН.РУ` на ваш поддомен.

Проверка (на сервере): `curl -s http://refs.ВАШ-ДОМЕН.РУ | head -3`
— должен начаться с `<!DOCTYPE html>`.

---

## Шаг 9. HTTPS (обязательно: без него не заработает микрофон)

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d refs.ВАШ-ДОМЕН.РУ --agree-tos -m ВАШ-EMAIL@example.com --non-interactive
```

Если выдало ошибку про соединение — DNS ещё не обновился: подождите
(проверка: `nslookup refs.ВАШ-ДОМЕН.РУ` должно показать IP сервера) и повторите.

Certbot сам настроит сертификат и перенаправление на https + автопродление.

---

## Шаг 10. Финальная проверка с телефона

Откройте **https://refs.ваш-домен.ру**:

1. Логотип DM, тёмная тема, каталог референсов.
2. **Вход** → пинкод `2026` → можно комментировать, голосовать, рисовать.
3. **Админ** → ваш `ADMIN_PIN` → «+ Добавить видео».
4. Голос: откройте референс → «Голос» → разрешите микрофон
   (микрофон работает **только по HTTPS** — поэтому шаг 9 обязателен).

После проверки Netlify больше не нужен — проект там можно удалить
(данные уже перенесены на ваш сервер).

## Что дальше

**Обновления** (когда я буду менять код) — на сервере:

```bash
cd /opt/dominoki && git pull && systemctl restart dominoki
```

**Бэкап данных** (рекомендуется раз в месяц):

```bash
tar -czf /root/dominoki-backup-$(date +%F).tar.gz /opt/dominoki/data
```

Данные лежат в `/opt/dominoki/data` — референсы, комментарии, фото и наброски.

---

## Если что-то не работает

| Проблема | Что сделать |
|---|---|
| Сайт не открывается по домену | `curl -s localhost:3000 \| head -3` (сайт жив?) → `nginx -t` (ошибки nginx?) → `systemctl status dominoki` |
| Ошибка 502 Bad Gateway | `journalctl -u dominoki -n 50` — причина в логах |
| Не загружаются фото | В nginx задан `client_max_body_size 20m` — проверьте строку |
| Не работает микрофон | Нужен HTTPS — проверьте, открывается ли сайт по https:// |
| Не входит по пинкоду | Проверьте `cat /opt/dominoki/.env` (ADMIN_PIN на месте?) → `systemctl restart dominoki` |
| Ошибка при установке Node | `apt install -y curl` и повторите команду с nodesource |
| Не приходят обновления GitHub | Проверьте, что репозиторий открыт (шаг 2) |

Логи сайта в реальном времени: `journalctl -u dominoki -f` (выход — `Ctrl+C`).
